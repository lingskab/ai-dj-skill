# Set 编排方法

## 1. 先给本场一个音乐方向

默认审美参考 Fred again..、John Summit、Gryffin、Martin Garrix、Avicii、Calvin Harris、BUNT.，不是每场必须全部出现。结合现场证据与口头要求，选择一个主轴：例如律动稳定的开发、低干扰的阅读、逐步提振的收尾。不把“看代码”等同于“需要高能音乐”。

优先熟悉曲建立个人感，也留出适配主轴的新曲位置；不预设固定收藏比例。用户反馈的“太吵、人声太多、没推进感、喜欢这段”优先于屏幕推断。

## 2. 骨架是可调整的路线

先遵从用户给定的总时长与音乐偏好。跨曲风演出不设平均分配、固定交替或 1:1:1 配额；从情绪、律动、速度和熟悉度的连续变化决定每种风格何时出现、停留多久。30–60分钟可采用 Warm-up → Build → Flow → Peak → Sustain，阶段可合并或弱化；两小时演出同样按情绪路线扩展，不按曲风配额填满。专注工作可以只有轻峰值，不强行演成音乐节。一个45分钟示例：暖场0–7、推进7–15、稳定15–28、轻峰值28–35、保持35–45；这是起点，不是配额。

先确定每阶段的功能和能量范围，再选曲填位置，避免凑够歌曲才贴阶段标签。每个骨架包含：目标、阶段/预计时间、歌曲准确版本/时长、邻接理由、可替换候选、属性来源及信心。逐曲相加计算时长，依据用户要求的总时长检查偏差；不要用曲目数、界面取整时长或假定的 AutoMix 重叠代替计算。超出约 ±1 分钟时，先寻找能改善曲序且接近目标的换曲/版本；若仍保留偏差，播放前说明预计超出或不足多少。完整单曲优先；截短的 DJ Mix 片段可能依赖原混音前后文，只有明确适配时才使用。

## 3. 属性与相邻关系

分别评估：

- 速度与律动：BPM、半拍/倍拍解释、鼓组密度、house/garage/DnB等节奏差异。数值近不代表体感一致。
- 和声：已知调性和兼容关系；Camelot相邻只作候选筛选，不能替代试听。
- 乐句和结构：intro/outro、breakdown/drop、可用衔接段；避免连续两首长breakdown让工作节奏塌落。
- 人声与频谱：避免密集人声叠加，考虑鼓/低频冲突、亮度与响度差。
- 情绪和能量：推进具有理由，峰值不等于最高BPM；熟悉度和歌词也会增加注意力占用。

属性来源优先实际可访问的可靠元数据/授权分析结果与试听记录。Apple Music/MCP 未提供的属性写未知，不宣称已解析 DRM 音频，不为获得数值开发自定义混音或绕过音频保护。

按“明显冲突先排除→功能适配→相邻兼容→个人偏好→新鲜感”决策。不要制造伪精确总分。两首属性未知时可以低信心试播，但需保留替代曲和听感反馈入口。

## 4. 原生 AutoMix 的角色

按当前实际设置核实 AutoMix，不假定每首/每个输出设备都支持同样效果。原生算法负责执行过渡；Agent负责候选、顺序和实际结果验收。系统可见的自动过渡说明作为约束线索，不能据此声称已获得每对歌曲的内部过渡计划。

留足分析与预载时间；在歌曲尾段/已开始过渡时优先延续，推迟到下一首再调整。若不知道安全窗口，避免末尾30秒或最后约15%时主动插曲（经验性默认，可据实测调整，非Apple规格）。

## 5. 实时决策

先问“保持现状是否已经合适”。短暂浏览消息不是立即换曲的理由。自主情境调整通常需要连续两次观察支持；用户明确指令可立即生效。

插曲必须回答：为什么现在变、如何接当前、如何回接后续、是否挤压或移动原Peak、是否有更温和的备选。使用下一首插入后，原下一首顺延，不默默删除原骨架。

播放前后记当前曲/进度/状态和准确队列位置。采样连续仅证明未重置或明显中断，不能证明毫秒级无缝。自然进入新增歌曲才能验收“下一首实际执行”；AutoMix开关为on不能代替听感验收。

## 6. 评价本场

把六个维度分开：个人适配、能量叙事、相邻兼容、音乐注意力负担、实际过渡、控制可靠性。专业 Set 质量要靠逐对过渡和整段听感证明；没有证据时称“有结构的候选 Set”。

在本地session记录只存决策所需摘要、歌曲和属性，不保存原始屏幕私人内容。维护pending/observed/verified状态：启动目标≠实际播放，入队≠已播放，连续进度≠音频无缝。


### 实战迭代（2026-10-28，两小时跨曲风场）

- 用户明确要求不要硬性 1:1:1 后，按情绪与速度编排的歌单自然顺播到第 8 首；逐曲读回确认 30 首。曲目时长合计 **2:02:04**，但 Music.app 摘要只显示“2小时”。此前曾产生不准确的总长陈述。今后必须从逐曲时长重新求和并核对，不能从摘要或旧计算继承总长；启动前处理超过容差的偏差。
- 实际播放已观测前段自然推进，但未逐对试听 AutoMix，也没有完成整场两小时耐久观察；证据只支持“已启动、若干曲目按序播放”，不支持全场长度或整体过渡验收。
- 巡检后期，当前播放来源与本场歌单不一致。操作者/原因未确认。正确处理是保留现状、不自动切回，并删除本场 heartbeat；以后以“当前来源歌单 + 曲目在该歌单中的位置”校验会话，发现不一致时先复核，确认离场后结束巡检。
- Music.app 队列列表呈现旧曲目，视图还含“历史记录”等分区；可见项不足以证明这些旧曲是即将播放还是历史。不要因此清队列，也不要把模糊队列视图写成队列验收。只读到明确分界及下一曲时，才记录对应范围的验证结论。
